# 数据结构说明

## 目标

Windows 端继续使用 SQLite，Android 端后续使用 Room。两端第一阶段不共享数据库文件，只共享 CSV / JSON 字段和语义。

机器可读 schema 放在：

- `shared/data_schema/video_snapshot.schema.json`
- `shared/data_schema/video_history.schema.json`
- `shared/data_schema/export_record.schema.json`

## 视频基础信息字段

| 字段 | 类型 | 可空 | 单位/说明 |
| --- | --- | --- | --- |
| `platform` | string | 否 | 固定为 `bilibili` |
| `bv_id` | string | 否 | 标准 BV 号，对应 Windows 端 `bvid` |
| `aid` | integer | 是 | B 站 aid |
| `title` | string | 是 | 视频标题 |
| `author_name` | string | 是 | UP 主名称，对应 `owner_name` |
| `author_mid` | integer | 是 | UP 主 mid，对应 `owner_mid` |
| `duration` | integer | 是 | 视频时长，秒 |
| `pubdate` | integer | 是 | 发布时间 Unix 秒级时间戳 |
| `source_url` | string | 是 | 原视频 URL |

## 单次采集快照字段

| 字段 | 类型 | 可空 | 单位/说明 |
| --- | --- | --- | --- |
| `collected_at` | string | 否 | ISO 8601，必须带时区 |
| `view_count` | integer | 是 | 播放量 |
| `danmaku_count` | integer | 是 | 弹幕数量 |
| `reply_count` | integer | 是 | 评论数量 |
| `favorite_count` | integer | 是 | 收藏数量 |
| `coin_count` | integer | 是 | 投币数量 |
| `share_count` | integer | 是 | 分享数量 |
| `like_count` | integer | 是 | 点赞数量 |
| `online_count` | integer | 是 | 当前观看人数的数值解析结果 |
| `online_text` | string | 是 | 当前观看人数原始显示文本，如 `3000+` |
| `source_type` | string | 是 | `collected` / `imported` / `manual` |
| `source_note` | string | 是 | 数据来源说明 |
| `fetch_status` | string | 否 | `success` / `partial` / `failed` |
| `error_message` | string | 是 | 成功时为 null 或空字符串 |

## 历史趋势字段

历史趋势由同一 `bv_id` 的多个快照按 `collected_at` 升序组成。趋势图不得假设每个指标都非空；如果某个字段为 null，应跳过该点或显示为缺失。

## 导出 CSV / JSON 字段

CSV 建议字段顺序：

```text
platform,bv_id,aid,title,author_name,author_mid,duration,pubdate,collected_at,view_count,danmaku_count,reply_count,favorite_count,coin_count,share_count,like_count,online_count,online_text,source_url,source_type,source_note,fetch_status,error_message
```

JSON 单条记录应符合 `video_snapshot.schema.json`。多条历史记录应符合 `video_history.schema.json`。

## 兼容策略

- B 站接口字段缺失时，对应字段写 `null`，不要伪造 0。
- 响应部分成功时使用 `fetch_status = partial`。
- 请求失败时使用 `fetch_status = failed`，保留 `error_message`。
- 数量字段统一使用 integer。
- 时间统一使用 ISO 8601；导入旧 CSV 时应尽量补齐时区。
- 新增字段必须先更新 `shared/data_schema/`，再更新 Windows 和 Android 端代码。
