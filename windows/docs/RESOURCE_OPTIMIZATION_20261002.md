# Windows 资源占用优化（2026-10-02，本地迭代）

基线为 `be3a662`，工作分支为 `codex/windows-resource-optimization`。不修改安卓、不推送、不构建安装包、不升级版本号。实际用户任务和数据库保持原位，验收进程继续使用 `%LOCALAPPDATA%\BilibiliMonitor\runtime-data`。

## 先测量，再优化

实际旧进程及其 WebView2 子进程采样 60 秒：专用内存合计 408.7 MiB，累计 CPU 0.344 秒。这台机器有 16 个逻辑处理器，约为整机 CPU 的 0.036%。这是静置及少量 HTML 请求探测的样本，不包括所有可能的采集负载。

原生窗口对比使用同一份实际数据库的 SQLite 一致性副本、独立 WebView2 配置目录、1150×800 窗口。两个版本均关闭测试副本的调度器，避免重复采集。依次访问首页、折叠详情、展开并滚动到双轴图、再次折叠、切换主题、隐藏到托盘；每个场景等待 3 秒，然后采样 15 秒。包含 Python/.NET 窗口壳及其全部 WebView2 子进程，排除 Windows 搜索、Codex 和其他应用的浏览器进程。

| 首页 | 285.6 | 298.0 | 0→0 |
| 初始折叠详情 | 398.9 | 329.3 | 11→0 |
| 展开一个图表 | 399.3 | 372.5 | 11→1 |

初始详情减少约 69.6 MiB（17.4%），打开一个图表减少约 26.8 MiB（6.7%），本轮操作后托盘减少约 34.3 MiB（7.5%）。首页未表现出节省，出现约 12 MiB 波动。这里的专用内存是 Private Bytes，属于进程私有提交量；工作集也保留在 JSON 中，但多个进程的工作集相加可能重复统计共享页，不能直接当成独占物理内存。

原生短场景 CPU 占整机约 0.02%～0.65%，前后波动并非所有场景都下降，不能据此宣称 CPU 持续明显降低。优化后实际验收进程另采样约 129 秒：平均 0.092%，1 秒采样的峰值 1.895%，专用内存中位数 324.7 MiB、峰值 334.2 MiB。实际进程的前后启动时长、页面访问和采集时机不同，不把这个样本与旧进程直接计算提升比例。

**检测时两条用户任务仍为 300 秒间隔。未改用户设置，也未完成真实 60 秒频率下的长期压力验证。** 测试副本关闭采集，其 CPU 数据主要反映界面和窗口壳。详细数值见 [JSON 证据](evidence/resource-optimization-20261002.json)。

## 最终修改

1. 封面不再由详情页直接请求 CDN，而是请求同源版本化封面地址。首次下载后存入 `runtime-data/cache/covers`，再次访问或重启程序后直接读本地文件。数据库继续保存原始 CDN 地址，历史交换格式不变；原始地址变化时自动生成新缓存键。
2. 下载后只处理一次，等比例缩小到最长边不超过 960 像素，存为 WebP，降低后续图片解码、传输和大图占用。缓存最多 128 MiB / 512 张，写入时淘汰最旧文件；下载上限 5 MiB，像素上限 2000 万。只接受经过白名单检查的 HTTPS 地址，重定向逐跳验证，校验真实图片内容，临时文件写完后原子替换。同一时刻仅一个封面下载，合并并发重复请求，不阻塞服务事件循环。
3. 封面响应支持长期浏览器缓存和 ETag / 304。不变的封面 URL 继续复用已解码图片，保留上一轮预加载、稳定占位和无重复导航的修复。实际 HTTP 首次缓存约 1.0～1.3 秒，随后读取约 12～19 毫秒；原生 WebView2 再次读取约 13 毫秒，资源记录显示缓存命中时传输字节为 0。首次遇到新封面仍需要联网。
4. 图表以安全 JSON 传输，只有所属面板展开时才下载/执行 Plotly 并绘制。初始折叠详情不执行 11 个 `newPlot`。已绘制图表再次展开复用实例，保留缩放状态；折叠不反复销毁/创建。测试期间比较过清理实例方案，未带来即时内存归还且增加重新分配，最终采用复用。离开页面时 DOM 生命周期结束，但浏览器可能保留堆、图表库和 GPU 缓冲，并不保证马上降低进程提交量。
5. Plotly 库改为流式文件响应，避免每次请求把整个库读成 Python 字符串；增加浏览器缓存，并按 Plotly 版本区分 URL，避免后续升级复用旧库。独立导出报告仍嵌入完整图表库、支持离线查看，不受网页懒加载影响。
6. 设置中折叠的日志面板不再每 5 秒请求日志或原生窗口状态；展开时仍正常刷新。日志数据没有变化时不重复重建表格。保留已有的托盘隐藏停止业务刷新行为。

两条实际视频的详情 HTML 从约 137～139 KB 降到约 61～63 KB。后端仍会生成图表 JSON，冷启动还有 Plotly 首次初始化成本；实际详情请求时间未显示稳定变快，不把 HTML 缩小等同于后端 CPU 加速。

## 验证与后续测量

- 133 项测试通过，包含显式 Windows 原生托盘测试。新增缓存并发合并、重启复用、缓存键变化、配额淘汰、恶意重定向、非图片/超大数据拒绝、ETag、JSON 安全和独立报告兼容测试。
- 真实 Evergreen 原生窗口验证首页、详情、单图绘制、折叠/展开复用同一数据对象、深浅色切换、封面加载、浏览器缓存命中和隐藏托盘；对比脚本正常关闭自己的测试服务。用户数据库未被测试数据覆盖。
- 开发测量脚本依赖现有开发环境中的 `psutil`，它不是应用新增运行依赖。

调整实际任务为 60 秒后，可对验收服务 PID 再采样数分钟，覆盖多轮真实采集：

```powershell
$monitorPid = (Get-NetTCPConnection -LocalPort 7860 -State Listen).OwningProcess
D:\python\python.exe scripts/sample_process_resources.py --pid $monitorPid --seconds 300 --output history/60-second-frequency.json
```
