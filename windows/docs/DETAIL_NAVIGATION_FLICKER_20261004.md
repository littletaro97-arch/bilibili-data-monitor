# 任务进入详情时的短暂闪烁排查

代码检查发现两条风险路径：

1. `motion.js` 在页面主体解析完成后启动 `main` 入场动画，首帧 `opacity:0`。当内容已经绘制，或详情内联脚本执行较慢时，可能出现“显示 → 消失 → 显示”。退出动画也淡出到 0，随后才开始页面请求，会让下一页加载期间持续空白。
2. 普通链接在跳转前恢复图表选择偏好，但任务卡片的鼠标点击与 Enter 直接使用不带偏好的详情地址。存在已保存偏好时，详情 head 的 `restoreChartPreferences()` 会执行 `location.replace()`，导致第二次文档请求。

无头浏览器回归在修改前确认第二条：保存 `left_metric=like_count` 后，点击卡片先请求不带参数的详情，再请求带参数的详情，单次入口共两次文档请求。不能把代码风险和请求复现等同于实体 WebView2 中的视觉复现。

修正：

- 统一卡片和普通链接的偏好 URL 生成，鼠标与 Enter 跳转均预先携带合法偏好，避免第二次请求。
- 页面入场改为 120 ms、2 px 位移；退出改为 80 ms、2 px 位移。整个主体不再淡出到透明，下一文档加载时保留当前内容。
- 保留展开/收起动画、减少动态效果偏好和历史缓存恢复逻辑；取消动画时清理离开标记，避免无法再次跳转。
- 更新 appearance.js 资源版本，避免已缓存旧脚本缺少新 URL 方法。

新增回归检查：保存图表偏好时鼠标和 Enter 仅加载一次详情；页面主体动画帧不设置透明；设置页面导航与后退后主体可见。既有导航测试覆盖标题外部视频、任务三个操作区域，以及悬浮目录。

隔离临时数据目录，完整测试启用无头/原生开关：**179 passed in 34.71s**。实体窗口的偶发闪烁仍需用户验收。

不改变数据采集和用户数据库，不打包/推送，不操作桌面或重启用户窗口。源码运行面板需重新打开首页后点击任务，已打开文档不会自动替换内联代码。

## 后续验收调整：恢复原过渡

用户反馈上一版过渡更自然，因此恢复原页面入场（160 ms 淡入＋4 px 位移）和退出（120 ms 淡出）效果，替代上文的纯位移方案。保留卡片鼠标/Enter 预先恢复图表偏好、避免二次文档请求、资源版本与动画取消清理。回归改为验证原淡入效果和单次请求；后退等待动画结束后检查页面可见，减少动态效果时仍跳过动画。此调整按用户视觉偏好恢复动画，不代表透明度相关风险已消除。
