# 目录与采集控制迭代

## 首屏与动画

原目录在 body 结束后才设置正文侧边留白，可能先绘制居中正文、再改变内边距。目录 CSS 现放入 head；appearance.js 在正文解析前读取开关、左右位置，正文从第一帧就使用正确留白。淡入初始状态也在 head 设置，避免已经显示的正文被末尾脚本重新设成透明；DOMContentLoaded 提供移除初始隐藏状态的兜底。保留原 160 ms 淡入/4 px 位移和 120 ms 淡出。

设置页目录开关和位置左右排列，窄于 600 px 时上下排列；去掉保存按钮，change 即保存。共享面板存储的其他标签页收到 storage 事件后也更新。目录高亮背景采用单一指示块，以 transform/height 配合 240 ms `cubic-bezier(.4,0,.2,1)` 移动，使用 IntersectionObserver 跟随章节，没有滚动轮询。菜单尺寸变化使用 ResizeObserver 校准；全部 details 展开/收起改为 220 ms 同一加减速曲线，保留快速切换取消处理与减少动态效果设置。

## 正文精简

删除评论检视台上方“本地文本，完整度未证实”及其计数、范围长说明。下方本通道样本、分 P、原文及数据口径继续保留。未把样本计数冒充历史覆盖率。

## 视频统计间隔

主页“立即采集”和“暂停/恢复”之间新增“修改采集时间”，点击打开输入框。单位为秒，最低取配置的 min_interval；最大 31,536,000 秒用于拒绝误输入及日期溢出。前后端均验证。

保存后从当前时间按新间隔安排下一次采集，不触发额外采集、不改变暂停/运行状态、不清除错误或平台冷却。进行中的采集完成后也从数据库读取最新间隔，避免旧内存值覆盖新计划。回收站任务不接受间隔修改。弹窗及操作按钮不触发任务卡片详情跳转。

## 评论、弹幕的调度与遍历

视频统计由 TaskScheduler 每 10 秒检查到期任务，根据每个视频的 interval_seconds 调度，并考虑抖动、失败/风险冷却。评论/弹幕的单页采样是手动触发，默认各自 600 秒最小重试间隔；登录分页采集也是手动、独立的后台任务，不跟随视频统计周期。它们共用 HttpClient 请求限速；共用限速不等于同步周期。本次不改成自动同步抓取，避免每轮视频检测都重新拉取大量文本。

添加可选“连续遍历到接口结束”：默认仍是每轮 150 批次；显式启用后最多 6,000 批次，遇平台限制、结构异常或请求失败立即暂停，断点逐批保留，不自动重试。评论按稿件遍历主评论和楼中楼，不按分 P 重复计算。接口结束不证明包含历史已删除/隐藏内容。

实际尝试《风的来信》：原 13 条，本轮累计读取 504 条，本地保存 517 条；处理 86 个批次后出现“平台请求或响应解析失败，进度已保留”，尚未遍历完成。《燕归来》也已启动尝试，重启前会保存断点。没有把部分结果宣称为全量。

## 可见性标记与保留

comments / danmaku 各增加 visibility、visibility_checked_at，旧数据默认为 unknown，不猜测其当前状态。新增原文显示并可筛选：

- 上次采集可见：采集接口曾返回有效正文；注明观察时间，不能保证此刻仍公开。
- 疑似已删除（接口占位）：评论正文返回常见删除占位文本。保留旧原文并归档；该占位也可能是用户手写文本，因此不标成“确认删除”。
- 当前可见性未核验：旧记录、没有正文的响应或本地数据；本地导入/演示另行标明来源。

再次返回正常正文后恢复“上次采集可见”。未再次返回的内容不删除、不自动标成已删除。当前弹幕接口未提供可靠的逐条删除证据，因此不能承诺自动识别已删除弹幕。公开/登录可见性受账号和接口范围影响，“公开采样”只是来源标记。完整 CSV 导出包含新增字段。

## 验证与回滚

隔离数据目录和无头/原生测试全部启用，**185 项通过**。新增检查覆盖首个 main 节点已具备正确留白（目录开/关）、设置自动保存、非匀速高亮/details 动画、间隔弹窗与前后端验证、暂停/冷却保留、采集中改间隔、删除占位原文保留、缺失样本不误判、连续遍历跨默认批次及风险立即停止。

运行数据库重启前以 SQLite backup 留存独立副本；字段迁移追加列，不覆盖旧正文。旧代码忽略新增列，可回滚 Git 后继续读取；需要彻底回退数据状态时停止程序后使用备份。只提交本地 Git，不打包、不推送，实体窗口效果由用户验收。
