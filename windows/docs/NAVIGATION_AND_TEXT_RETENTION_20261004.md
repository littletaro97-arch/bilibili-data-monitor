# 任务点击、详情目录和文本留存

本轮基线 `3f76bbf`，分支 `codex/task-card-navigation`。仅 Windows 源码和本地 Git；没有打包、推送或操作用户桌面，也没有重启当前验收程序。修改后后端及新增数据库表需要重启源码程序生效。

## 已修改

- 首页：任务卡片正文／指标区点击进入详情，卡片获得键盘焦点后可按 Enter。标题在新目标中打开原 B 站视频；沿用现有外部视频链接机制。立即采集、暂停／恢复、回收站按钮及整个操作区均不被卡片跳转覆盖。选择文字时也不触发跳转。
- 详情页目录：默认右侧，可在“设置 → 详情页目录”关闭或选左侧。偏好保存在当前面板 localStorage；浏览器与自有窗口各自保存。宽窗口展开，窄于 1600 px 收为目录按钮，避免常驻覆盖内容。可跳转视频概况、最新数据、趋势图表、历史导入、评论与弹幕及原文证据；进入折叠内容时先展开。高亮使用 IntersectionObserver，没有持续滚动轮询；低动态效果偏好关闭平滑滚动。
- 单页评论入口和结果提示明确写为“单页采样”，并指向下方“登录后遍历 → 评论及楼中楼”，避免把一次采样当成全量遍历。
- 历史留存：后续响应缺少某条评论／弹幕时，原记录不删除。评论为空或常见已删除占位内容时保留已有原文；平台修改了文本时，将旧文本保存到新增的 `comment_text_history` 表。全部数据导出包含该表，旧文与修订文都可追溯。没有将一次未返回判定为平台删除。

未采集过、已经被平台删除或不可见的内容，不能凭本地程序恢复。留存保证针对已经成功取得的内容；未直接修改实际运行数据库。

## WorkBuddy 词提取方案审查

已读取 `C:\Users\LittleTaro\Desktop\BilibiliMonitor-样本词提取改造` 的说明、推荐实现及验证代码，没有执行这些外部脚本，也没有安装 jieba；按原要求，本轮词排行算法未变。

确认的问题是 bigram 滑窗，不是按词切分：“六周年快乐”产生“六周／周年／年快／快乐”，没有中文词义边界，统计数量不能称为语义词频。

WorkBuddy 的分词、停用词和专名词典方向可参考，但不能原样套用：

1. 当前排行实际在 `text_panel.js` 的 `showWords` 中按筛选后的内容计算；材料假设是 Python 变量 `comment_top_words/danmaku_top_words`。不是直接替换同名函数即可接入。
2. 代码的 ASCII 长度过滤与词性白名单会排除有意义的英文名称，例如 `ChatGPT`。泛化至其他视频时不能使用游戏专名清单和停用词表作为通用标准。
3. `resplit` 依据虚字切分，会伤及含这些字的真实词；`merge_tail` 在过滤后的词列表中合并后缀，可能跨过原始标点或语境，拼出原文没有的词。词频结果应能对应到原文，不能创造词语。
4. 说明的“7.3 MB”是文件体积，不是运行内存；推荐实现导入时初始化全词典，并额外创建 `_JIEBA_KNOWN` 集合。实际运行内存及 10,000 条文本耗时尚未测量，不能按文件大小承诺性能。
5. “HMM 是唯一识别专名的机制”过于绝对，自定义词典也能保护专名。说明关于 `x`、`o` 标签的表述与白名单／显式 tag 代码亦有不一致之处，不应把示例回归当作一般语义正确性的证明。
6. 需要逐条文本分词，不把各条弹幕直接拼接后分词；否则跨弹幕边界也可能产生假词。缓存应按文本和词典版本区分；最小频次／小样本降级应在界面明确标注。

开发用无界面 Chromium 已验证支持 `Intl.Segmenter`，但测试“原神六周年快乐！温迪生日快乐，ChatGPT教程”仍切出“原／神六”和“温／迪”。原生分词同样需要专名保护，不能单独替换后声称中文语义正确。后续可比较“原生分词 + 小词典”与“独立按需分词进程”，实际 WebView2 的行为和准确率也需要验收。
