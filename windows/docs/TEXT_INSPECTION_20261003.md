# 评论与弹幕检视台、分 P 范围排查

基线 `dc527ce`。分支 `codex/text-inspection-dashboard`。仅本地 Git，不打包、不推送、不操作用户窗口。真实接口探测使用临时数据库；用户数据库只以 SQLite 只读模式检查过。

## 设计选择

读取用户提供的三个 HTML 作为布局参考，没有执行其中脚本或使用其示例数据。以方案 B 的弹幕／评论双通道为结构，采用方案 C 的样本观察与峰值排名，以及方案 A 的视频位置分布和关键词筛选。不采用没有数据依据的“实时新增、下降回落、告警”或定时轮询控件。

新面板提供：

- 平台计数、本地唯一样本、上次分 P 采样范围、去重与截断说明。
- 关键词任一／全部匹配、来源选择、分 P 选择、排序和可点击词片段排行。
- 样本量、命中量、样本内命中率、最密片段／评论最高点赞；结论明确限定为样本。
- 每 30 秒视频内分布（较长视频自动增大桶宽以限制柱数）、前三个峰值片段、片段下钻、可复制原文、高亮和每页 50 条分页。
- 中文使用双字片段排行，不宣称是完整分词或情绪分析。
- 本地导入／演示单独标记并默认排除；导入入口收进折叠区。
- 全局深浅色、窄屏布局、既有减少动态效果与折叠过渡。

不再用旧的前 200 条评论／500 条弹幕计算结论，或只显示 30／50 条原文。新面板最多加载每类最近 10,000 条唯一内容并明示截断；分页只保留 50 个原文 DOM 节点，普通柱图不依赖额外图表库，无新后台轮询。分析使用本地保存样本，平台总量带原统计时间，不假装同步的全量内容。

## 分 P 与统计口径

BV／aid 对应整个稿件，CID 对应分 P；`?p=2` 是播放分 P 参数，现有监测任务仍按 BV 管理稿件总量。单个分 P 的弹幕选择由检视台 CID 控制，不把稿件总量改称单 P 计数。

采样默认仅所选 P（未指定时为原默认 CID）。全部 P 必须明确选择，最多 10 个；超过上限会通过实际采样 P 数／稿件 P 总数体现未覆盖部分。提供只读取分 P 名称与 CID 的入口，60 秒同类冷却，不下载弹幕。后端重新核对 CID 属于该 BV，拒绝其他稿件的 CID。不同 CID 的弹幕时间分布与关键词结论分别计算。

评论区由稿件共用，界面隐藏评论通道的分 P 筛选，不按 P 重复采集或累加评论。平台返回的 reply/danmaku 稿件计数与实际文本样本分开展示。

新 XML 弹幕保存平台 ID 为字符串，避免大整数精度丢失；重复读取的相同记录在分析查询中合并。旧数据未保留 ID，按 CID、位置、发送时间、文本折叠；与新 ID 记录匹配时不再次计数，但同参数的不同旧弹幕仍可能被合并，界面明确此限制。不会删除或改写原弹幕历史。

两者旧采集均只使用第一 P 的 CID。第一 P 的 XML 样本位置跨度基本贯穿该 P，但不等于取得该 P 的每一条弹幕，更不等于其他语言 P 或所有历史弹幕。遍历全部 P 后仍仅是各自当前 XML 弹幕池。程序的解析上限是 10,000 条／P，本次返回 1,200 条是上游实际返回量，不是程序在 1,200 截断。

评论接口 `/x/v2/reply` 在两个视频上的 pn=1、ps=20、sort=2 都实际返回 3 条主评论；本次连同附带回复各保存 12 条。pn=2 返回空 replies、page 全零；sort=0 首页面同样返回空。不能据此推断实际只剩这些评论，或第二页之后为空；平台总量和接口文本明显不匹配。当前环境没有取得全部主评论、全部子回复、已删除或不可见内容。沿用单页低频采样，不以反复空页请求冒充全量；不绕过账号／平台访问限制。

若后续确实需要更接近完整内容，须另行验证分段弹幕或正式授权数据源，以及可用的评论分页与子回复契约，并独立证明范围和限速；不会将目前的接口样本描述为完整抓取。

## 验证与运行边界

完整 pytest 150 项通过，启用无窗口 Chromium 与原有原生托盘测试。覆盖选中单 P、默认 P、全部 P、跨视频 CID 拒绝、不同平台 ID 不误合并、旧新记录去重、分析截断、关键词规则、片段联动、分页、来源分离、HTML 文本安全、深浅色与窄屏溢出。已查看后台生成的深浅色截图；截图使用明确的测试样本，不是用户数据或桌面截图。

新建 `text_collection_runs` 元数据表、可空 `danmaku.source_id` 列和匹配索引；均由下次启动初始化增量创建，不重建、清空或修改既有记录。旧代码可忽略附加表／列，回滚应用代码不需要删除它们。没有升级公开版本号或构建包。

目前没有主动重启用户应用。旧进程若刷新模板会提示需重启加载检视服务；不会把新面板空状态伪装成已取得全量数据。退出程序后重新启动源码入口才能加载采样和数据库增量。复测命令：`python scripts/probe_public_text.py <BV号>`，明确在临时存储里探测全部 P，不改用户数据库。
