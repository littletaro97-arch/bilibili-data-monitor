# 登录后的评论分页与分段弹幕采集

本轮仅修改 Windows 源码并本地提交；不打包、不推送、不发布，也没有关闭或重启正在使用的窗口。未操作桌面、未读取用户浏览器 Cookie、未修改实际运行数据库。

## 对提供方案的判断

参考目录：`C:\Users\LittleTaro\Desktop\bili-panel`，检查了 README、采集报告、采集器、服务器和面板。该目录没有登录 Cookie 文件。

可采用的部分：SESSDATA 登录态、WBI 签名评论游标、主评论分页、楼中楼分页、6 分钟 protobuf 弹幕分段、扫码登录。

没有采用原服务器。它明文保存 Cookie，允许宽泛跨域访问，并把敏感参数放入 URL；原采集器还会在空分段、错误响应、缺少游标或达到页数上限时结束，容易把部分结果当作完成。命令行默认只读取第一个 CID。

“登录即可取得完整历史”缺乏证据。登录可以扩大可访问范围，但平台可能隐藏、删除或截断内容。稿件显示的评论／弹幕计数，也不等于接口实际可返回的文本数。本版显示“接口遍历结束，完整度未证实”，不声称获得所有历史内容。

## 使用方式

1. 设置 → Bilibili 登录采集 → 扫码登录，在手机客户端确认。扫码不可用时可手动填写 SESSDATA。
2. 视频详情 → 评论与弹幕检视台 → 登录后遍历评论与分段弹幕。
3. 选择弹幕或评论。弹幕默认仅下方所选 P，也可显式选择全部 P；评论区由整个稿件共用，采集一次，不按 P 重复累加。分 P 列表未齐时先点击“读取分 P 列表”。
4. 结果逐批保存。可暂停、从断点继续；程序退出后任务转为暂停，重启后可恢复。链接放入回收站时也会暂停该视频的文本采集，取回后可手动继续。恢复必须使用创建任务的同一 Bilibili 账户。
5. 点击“刷新本地结果”加载已保存文本。分析页最多载入最近 10,000 条唯一文本，超出会提示截断；完整已保存文本仍在 SQLite 中，可通过设置里的全部数据导出取得 CSV。

普通公开采样保留，仍是单页评论／XML 池样本，不需要登录。它与登录采集共同进入本地公开文本通道；本地导入／演示继续独立标记。

## 实现和资源约束

- 弹幕：读取视频分 P 列表，根据每 P 时长计算全部 6 分钟分段。空分段继续下一段；304、错误 JSON、解析失败不算已完成。保留平台 ID 字符串，以 BV + CID + 平台 ID 去重，避免大整数精度损失和跨 P 混合。
- 评论：WBI 签名，按时间模式逐页；以接口明确的结束标志结束。楼中楼继续分页，保留父评论关系；置顶重复主评论按 ID 合并，已读取完整楼层不重复翻页。无效或循环游标、楼中楼空页但仍有计数均暂停。
- 一次只运行一个登录文本任务；与常规检测共用请求锁和至少 3 秒间隔。每轮最多处理 150 个批次后暂停，可继续下一轮，不用固定总页数冒充遍历完成。
- 网络响应最多 8 MiB，单页评论最多 100 条，单分段最多 50,000 条。逐批解析和入库，不把整个视频文本堆在内存。大量数据 CSV 导出也改为逐行写入。
- 当前浏览器分析上限不是采集上限，也不是完整数据的统计结论。单次加载的文字片段排行／热点仍需注意截断提示。
- 平台限制／登录失效后停止后台请求，并设置持久化的 10 分钟登录采集冷却；新建任务也不能绕过该冷却。没有自动连续重试。
- QR 和进度只在有待处理登录／任务时轮询；隐藏窗口时跳过业务轮询。普通统计任务不自动携带登录 Cookie。
- Windows 当前用户 DPAPI 加密保存登录态；不保存 refresh_token。退出登录先暂停文本任务，再删除加密文件。加密文件、Cookie 文件及运行目录均不进入 Git。
- 登录／登录采集 API 仅允许本机访问，校验 Host、Origin 与跨站来源；所有变更使用 POST。账号凭据只发给固定平台 HTTPS 接口，不写入地址、HTML、进度或日志。
- 文本任务和游标表为新增表，没有删除或重写已有历史记录。回滚源码后已有评论和弹幕仍可供旧检视服务读取。
