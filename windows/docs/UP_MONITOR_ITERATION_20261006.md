# UP 主监控与面板细节迭代

日期：2026-10-06。基线：公开 Windows 0.13.0 · 安装包第 1 版；当前正式安装的冻结 EXE 已只读核对为该版本，GitHub 暂无更高 Windows 正式版。本轮在独立 codex/up-monitor-and-report-controls 分支实施，不打包、不推送、验收前备份数据并退出正式安装，启动修改后的源码；不覆盖正式安装 EXE。

## UP 更新检测

首页位置：任务列表下、其它设备访问上。支持 UID、UP 空间链接或视频链接反查主投稿作者。复用已有 BiliAuth 和固定 api.bilibili.com HTTPS 通道，不扩大 Cookie 白名单，不加入设备指纹或搜索接口降级。使用项目现有完整 WBI 签名表；参考目录中的部分示例表不完整，不能直接复制。

UP 检测默认 300 秒、最低 120 秒；新视频统计间隔另行设置，最低跟随原有视频配置。添加成功后记住这两个默认值。每个 UP 支持暂停/恢复、立即检测、修改今后间隔和移除。暂停 UP 只停止发现新稿，已加入的视频继续采集；移除 UP 后已加入的视频留在普通任务列表。

首次成功列表只记录发布时间和 BV 基线，不创建任何视频任务。后续按发布时间和已见 BV 去重；置顶旧稿不会当作新稿，同秒连发新稿可检测。发现记录和新基线同一事务持久化，然后尝试加入已有视频队列。全局运行任务上限保持原值，满载条目持久化为待加入，不顶掉现有任务。已有手动或回收站任务不被重新激活/覆盖。

新任务最初快照标记 UP_MONITOR。新稿在 UP 分组内展开，支持移至普通任务列表。首页每 60 秒请求轻量状态；只有分组变化才刷新页面，隐藏/最小化、编辑输入或弹窗打开时延后刷新；检测时间就地更新。

请求分页最多 10 页、每页 30 个记录，越界或异常不推进新基线。风控停止本轮、UP 通道共享冷却；登录失效暂停 UP 检测，重新扫码后需手动恢复。暂停/移除期间完成的元信息请求不会再新增任务。轮询时间受平台限速、队列和网络影响，统计曲线从实际发现开始，不能补齐发布到发现之间的历史。

## 真实接口验证

使用本机已保存登录态做低频只读请求，未读取凭据到工具输出、未添加真实监控或视频任务。UID 546195 的首个列表返回 30 条，其中 3 条主投稿作者不同，空间计数为 678（包含合作投稿）。用户明确合作投稿也属于该 UP，因此列表中的合作记录一并纳入该 UP 的检测；视频详情仍保留平台实际主投稿作者。UP 名称只从该 UID 的主投稿作者字段取得，若全是合作投稿则显示 UID，不误用合作方名字。接口本轮可用并不保证所有账号/UP 永久可用。脱敏结果见 evidence/20261006/up-provider-live.json。

## 面板与报告

- 采集间隔弹窗、确认弹窗及表单跳转复用 160 ms 淡入/4 px 位移和 120 ms 淡出；评论/弹幕通道、扫码图也增加同款轻过渡。遵守减少动态效果，无循环动画。
- 设置的两列用 Grid stretch 自动等高，右侧后续高度变化仍自动匹配；窄屏保持上下排列。
- 打开 HTML 报告在本机调用系统浏览器的 HTTP 协议地址，应用继续停留详情。该桌面动作拒绝非本机与跨站请求。
- 新增报告登记与删除按钮，删除需确认；只删除指定报告文件，不删除视频/快照。已生成的旧报告从已有文件及原生成日志登记。登记后文件被移动/删除时，显示复用主题警告色的“路径已改变”。登记前已移走且无生成日志的文件无法凭空恢复记录。
- 已删除记录保留删除标记，避免旧日志在下次打开页面时把已删报告再次列出。路径已改变时删除只清理登记，不扫描或删除未知新路径。
