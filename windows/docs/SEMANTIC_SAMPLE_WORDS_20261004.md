# 样本词语排行改造（2026-10-04）

## 原因与选择

旧前端对中文连续文本逐字滑动取两个字符，因此“原神六周年快乐”会产生“神六、六周、年快”。这不是中文分词。WorkBuddy 提供的是 demo，不要求接口与产品一致；其自定义词典、停用词、噪声过滤和低频回退值得采用。

本次采用浏览器自带 `Intl.Segmenter('zh', {granularity:'word'})`，配合最长连续专名匹配，不增加 Python 分词依赖或全量外部词典。原生分词独立使用时也会拆错游戏名称，因此加入原神、温迪、绫华、六周年、生日快乐等保护词，吸收 demo 中的游戏、地区、机制词。

没有移植 demo 的以下规则：

- 按长英文、短英文长度一律过滤：会误删 ChatGPT、OpenAI、API、AI 等有意义名称。
- 根据“之、与、于”等字二次切词、过滤后拼接后缀：可能破坏真实词语或构造原文不存在的词。
- 拼接所有评论再分词：会跨条目生成新词。
- 用词典文件大小推断运行内存：文件大小不等于解释器对象及词典驻留内存。

词语必须来自单条原文的连续片段；专名不跨标点或 URL 拼接，URL、BV 号、纯数字及常见功能词过滤。中文单字不进入此排行，因此仍会漏掉单字专名；自定义专名最短 2 字。它是词语出现次数排行，不是情绪分析；“不快乐”中出现“快乐”也不能直接解释为正向情绪。

## 前端与统计口径

- 标题改为“样本词语排行”，明确显示分词、计数及筛选口径。
- 默认只排出现至少 2 次的词；没有达到门槛的词时回退到 1 次，并显示提示。
- 同一条内重复出现重复计数；最长词优先，不重叠再计其内部短词。因此新旧词频不能直接比较。
- 排行取当前通道、当前来源、当前分 P 的全部已加载唯一样本，不随关键词或时间片段筛选重算。
- 点击词语仍按原文包含关系筛选，所以命中条数可能不同于分词出现次数。
- “补充分词专名”每行一个词，最多 200 词、每词 2–30 字，最多 10,000 字符；中文、字母、数字、下划线可用，纯数字拒绝。
- 用户专名保存在当前浏览器存储中，按 BV 隔离；本机窗口和外部浏览器使用各自存储，不同步到其他设备。保存失败提示本次生效、刷新失效；空词典恢复内置词典。
- 无 `Intl.Segmenter` 的旧内核明确显示降级提示，仅保留词典专名和英文，不退回双字截取。
- 本次只改面板词语排行；采集、原文、分 P、既有文本保留与报告算法不变。

## 性能与实测

逐条分词结果采用 LRU：最多 2,048 条不同文本，并限制缓存文本与词语累计长度 500,000 UTF-16 单位；这不是字节级内存承诺。另按通道、来源、分 P 缓存最多 12 组排行结果；关键词筛选、列表排序和密度片段选择复用排行。更换专名清空相关缓存，重新计算。

通过 `scripts/benchmark_sample_words.py` 的 SQLite `mode=ro` 读取现有数据库，未改写用户样本；无头 Chromium 测量本次 8,750 条公开去重弹幕：

| 指标 | 单次观测 |
| --- | --- |
| 首次分词与排行（含初始化） | 44.4 ms |
| 复用分词缓存、重新统计 | 10.4 ms |
| 旧双字计数（未含完整旧排行/DOM） | 7.4 ms |
| 缓存不同文本 | 1,562 条 |
| 缓存累计字符单位 | 23,594 |

新算法首次计算更贵，不能声称比分双字快；面板通过结果缓存避免重复计算。以上不是整个程序 CPU/RAM 指标，也不是实体 WebView2 验收结果。

真实排行对比：旧“年快 6037、六周 5914、华生 972、日快 1031、神六 270”消失；新“六周年 5911、生日快乐 1030、绫华 1014、原神 390、温迪 239”。“快乐 6024”不重复计入“生日快乐”的内部子词。冷门词及中文歧义仍可能存在，可补充专名；不宣称达到完美语义理解。

## 验证与验收

新增浏览器回归覆盖截图错切、英文名称、跨条/标点隔离、补充 Unicode 专名、大小写合并、噪声、低频回退、旧内核降级、缓存上限。面板集成检查词语点击筛选、专名保存/刷新恢复、无效输入拒绝，以及既有分 P、分页、深色模式和窄屏布局。

隔离临时数据目录并启用无头/原生测试开关，完整测试结果：**178 passed in 34.77s**。未使用 Computer Use。
