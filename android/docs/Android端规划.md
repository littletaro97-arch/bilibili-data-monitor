# Android端规划

## 当前结论

Android 端从 `v0.3.0` 开始进入 MVP。`v0.2.0` 只做规划、schema 和文档，不创建完整 Android 业务代码。

## MVP 第一阶段范围

只做：

1. 输入 BV 号或视频链接。
2. 解析 BV 号。
3. 手动刷新获取基础视频数据。
4. 本地 Room 数据库保存快照。
5. 列表页展示视频。
6. 详情页展示最近一次快照。
7. 简单历史趋势图。
8. 导出 JSON / CSV。
9. 本地日志页面。

暂不做：

1. 高频后台监控。
2. 自动绕过登录。
3. 验证码处理。
4. 代理池。
5. Cookie 自动抓取。
6. 评论全文大规模抓取。
7. 弹幕全文大规模抓取。
8. 鸿蒙端。
9. 云端同步。
10. 付费服务器。

## 推荐技术路线

- Kotlin：主语言，减少 Java 模板代码。
- Android Studio：标准构建和实机调试环境。
- Jetpack Compose：MVP 页面简单，适合快速迭代。
- Room：本地 SQLite，适合快照历史和日志。
- OkHttp：MVP 阶段比 Retrofit 更轻，后续接口稳定后可再封装。
- kotlinx.serialization：JSON 导入导出和 schema 对齐。
- WorkManager：只用于后续低频任务，不作为 MVP 首要目标。
- 图表库：优先评估 MPAndroidChart 的稳定性；若 Compose 图表库维护不足，不要为了纯 Compose 强行采用。

## 不推荐技术路线

- WebView 包装 Windows 页面：不能解决本地 Room、导出、通知和后台限制，调试成本更高。
- React Native：后台任务、前台服务、Room、权限都要桥接，当前收益不足。
- Flutter：UI 可行，但原生后台和通知仍需平台代码；对这个 MVP 不是最小路径。
- Java 原生：可行但 Compose 和 Kotlin 生态更适合后续维护。
- 隐藏保活方案：不可靠，也不符合项目边界。

## 页面结构

- 首页：视频列表、最近刷新时间、失败状态。
- 添加页：输入 BV 号或链接，显示解析错误。
- 详情页：视频基础信息、最近一次快照、简单趋势图。
- 导出页：导出 JSON / CSV，显示本地文件路径。
- 日志页：本地请求、解析、数据库和导出日志。
- 设置页：刷新超时、最低间隔、数据清理。

## 数据流

1. 输入文本。
2. 解析为 `bv_id`。
3. OkHttp 请求公开数据源。
4. 响应映射为 shared schema 字段。
5. Room 写入视频基础信息和快照。
6. UI 从 Room 读取并展示。
7. 导出模块按 `shared/data_schema/` 输出 JSON / CSV。

## Room 表建议

- `videos`
- `video_snapshots`
- `crawl_logs`
- `export_records`

字段必须参考根目录 `数据结构说明.md` 和 `shared/data_schema/`。

## 网络请求规则

- 固定公开数据源。
- 设置超时。
- 遇到 403、412、验证码、风控、登录要求或异常结构时标记失败。
- 不自动寻找替代接口。
- 不注入 Cookie。
- 不伪造设备指纹。

## 日志方案

本地日志至少记录：

- 时间
- 操作类型
- `bv_id`
- 请求状态
- 错误类型
- 简短错误信息

不得记录 Cookie、账号、密码、完整敏感响应。

## 实机调试步骤

1. 安装 debug APK。
2. 输入一个公开视频 BV 号。
3. 手动刷新。
4. 检查详情页最新快照。
5. 检查 Room 数据。
6. 导出 JSON / CSV。
7. 与 `shared/data_schema/` 对照字段。
8. 记录到根目录 `实机测试记录.md`。

## 版本路线图

- `v0.3.0`：Android MVP 工程、BV 解析、Room schema、手动刷新。
- `v0.3.1`：列表页、详情页、最近快照展示。
- `v0.3.2`：趋势图、JSON / CSV 导出。
- `v0.3.3`：日志页和错误状态。
- `v0.4.0`：Android 构建流程固化、错误提示、导出反馈和 UI 稳定化。
- `v0.5.0`：WorkManager 低频任务、趋势展示和导出分享。
- `v0.5.1`：自动刷新设置入口和 WorkManager 状态热修复。
- `v0.6.0`：自动刷新诊断区、手动测试任务、批量刷新和日志筛选。
- 后续版本：Windows + Android 数据格式统一验证。

## v0.3.0 落地情况

v0.3.0 已创建 Android 原生工程并完成 MVP 原型：

- 工程根目录：`android/`
- 应用模块：`android/app/`
- 技术栈：Kotlin、Compose、Material 3、Room、OkHttp、Coroutines、JUnit。
- 数据范围：公开视频基础信息和统计字段。
- 触发方式：仅手动刷新，不做后台高频采集。
- 导出格式：JSON/CSV，字段尽量对齐 `shared/data_schema/`。

已实现页面：

- 首页 / 视频输入页
- 视频详情页
- 历史记录页
- 导出页
- 日志页

v0.3.0 不包含：

- WorkManager
- 前台服务
- 登录系统
- Cookie
- 验证码处理
- 风控绕过
- 代理池
- 高频后台监控

后续 v0.4.0 不应直接扩大采集频率，应先完成实机安装、Room 数据检查、导出路径验证和错误提示优化。

## v0.4.0 落地情况

v0.4.0 定位为 Android 实机稳定性验证和构建流程固化，不扩大采集能力。

已完成：

- 固化 `android/scripts/build-ascii.ps1`，统一 Android test、assembleDebug、APK 复制和 release 文档生成。
- Android 版本升到 `0.4.0`。
- 导出成功后显示文件名、导出时间和绝对路径。
- 网络错误提示区分无网络/DNS、超时、HTTP 403、HTTP 412、登录、验证码、风控、字段缺失和 JSON 解析失败等场景。
- 日志级别统一为 `info` / `warning` / `error`，关键操作写日志。
- 日志页明确显示最近 200 条日志，按时间倒序。
- 详情页刷新和导出按钮增加 loading 防重复点击。
- 历史记录和日志页补空状态。
- v0.3.0 用户手动实机反馈已写入根目录 `实机测试记录.md`。

未完成：

- Codex 未进行 v0.4.0 实机安装测试。
- 未引入 WorkManager。
- 未做趋势图增强。
- 未做外部公共目录写入或高风险存储权限申请。

## v0.5.0 落地情况

v0.5.0 定位为 Android 低频刷新和趋势增强，不引入高频保活。

已完成：

- 使用 DataStore 保存自动刷新设置，默认关闭。
- 设置页支持开启/关闭自动刷新，间隔为 15 分钟、30 分钟、1 小时、3 小时、6 小时。
- 使用 WorkManager 周期任务刷新已经添加的视频。
- 自动刷新日志覆盖注册、取消、重调度、Worker 执行、完成和失败。
- 历史页基于本地 Room 快照展示播放、点赞、评论、投币、收藏趋势。
- 趋势窗口支持最近 20/50 条；空数据和单点数据安全显示。
- 导出页显示文件名、绝对路径、大小和时间。
- 通过 FileProvider 调用 Android Sharesheet 分享导出文件，不申请宽泛存储权限。

未改变：

- Room schema 未变化，数据库版本仍为 1。
- 不新增视频发现。
- 不采集评论/弹幕。
- 不做登录、Cookie、验证码、代理池、风控绕过或高频后台监控。

需要实机验证：

- 不同厂商省电策略下 WorkManager 实际执行延迟。
- 导出文件分享目标 App 兼容性。
- 长时间积累快照后的趋势页滚动体验。

- 增加注册/取消/重调度的纯 Kotlin 测试。

未改变：

- 不做高频后台任务。
- 不做隐藏保活。
- 不新增评论/弹幕采集。
- 不绕过登录、Cookie、验证码、代理池或风控。

下一步：

## v0.7.0 落地情况

v0.7.0 定位为 Android 可用性修复和系统存储交互修复，不扩大采集范围。

已完成：

- App shell 使用安全绘制区域，避免顶部导航被状态栏、刘海屏或挖孔屏遮挡。
- 顶部导航按是否存在有效选中视频动态显示，未选中时不暴露详情和历史。
- 选中视频从列表消失时清理选择，避免详情/历史页对不存在视频继续高亮。
- 直接导出改为 Storage Access Framework：首次打开系统保存窗口，默认目录通过 `OpenDocumentTree` 另行授权。
- 默认目录直存时检查持久化写权限，授权失效时清理设置并回退系统保存窗口。
- 默认目录直存避免同名覆盖。
- 保留 FileProvider + Android Sharesheet 分享导出文件。
- 设置页按功能分类重排，网络约束开关整行可点击。

未改变：

- Room schema 未变化，数据库版本仍为 1。
- 不新增视频发现。
- 不采集评论/弹幕。
- 不做登录、Cookie、验证码、代理池、风控绕过或高频后台监控。

需要实机验证：

- 不同 Android 版本和文件管理器下的系统保存窗口行为。
- 默认目录授权后后续导出是否直存成功。
- 默认目录被撤权或删除后是否能回退系统保存窗口。
- 刘海屏、挖孔屏、横竖屏切换下顶部导航是否仍无遮挡。

## v0.8.0 落地情况

v0.8.0 定位为崩溃修复和界面可用性修复，不改变 Android 端单 Activity、本地 `Page` 状态和 Repository 数据访问方式。

已完成：

- 高级页改为单一主滚动列表，日志筛选和日志卡片作为同一个 `LazyColumn` 的 item 渲染。
- 首页、详情、历史、设置、高级页面内容区由根布局 `weight(1f)` 约束高度，避免页面内滚动组件获得无限高度。
- 详情页最近快照随页面滚动展示，解决较小屏幕或字体放大时底部字段不可见的问题。
- 首页移除自动刷新设置入口；设置页保留自动刷新开关、间隔、网络约束、调度状态和手动调试按钮。
- 自动刷新间隔使用滚轮式固定档位：1m、3m、5m、10m、15m、30m、1h、2h。
- `RefreshIntervals.backgroundScheduleMinutes()` 明确 WorkManager 后台有效周期最低 15 分钟。
- 长标题、日志详情、错误详情和诊断区支持展开 / 收起。

未改变：

- 不新增视频发现。
- 不采集评论/弹幕。
- 不做登录、Cookie、验证码、代理池、风控绕过或高频后台监控。
- 不做隐藏保活或前台服务规避系统调度。
- Room schema 未变化，数据库版本仍为 1。

需要实机验证：

- 高级页在无视频、有视频、有日志、无日志状态下均不闪退。
- 详情页最近快照在小屏、横屏和字体放大下可完整滑动查看。
- 手势导航和三键导航下底部没有异常空白或遮挡。
- 滚轮选择间隔的触摸拖动、点击选择和设置恢复。
- App 后台返回后页面和折叠状态是否符合预期。
